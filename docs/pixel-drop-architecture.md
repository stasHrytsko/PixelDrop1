# Pixel Drop: игровая архитектура

## Цель

Структура должна позволять независимо менять правила, добавлять уровни,
перерисовывать интерфейс и улучшать touch-управление. Поэтому ни графика, ни
обработчики жестов не изменяют состояние игры напрямую.

## Слои и зависимости

```text
levels ───────────────┐
                     v
index → application → engine
            │          ^
            ├→ render  │
            └→ input ──┘  (только через callback игровых намерений)
```

- `engine` — доменная модель. Создаёт состояние и применяет `GameInput`.
  Не знает про DOM, pointer events, звук, хранилище, Capacitor или уровни.
- `levels` — контент и его граница доверия. JSON проходит runtime-валидацию:
  размер 10×10, ровно шесть фигур, уникальные id, корректные цвета, валидная
  стартовая расстановка, одинаковый цветовой инвентарь и собираемость рисунка.
- `render` — графическое представление. Получает `LevelState`, строит DOM и
  обновляет классы/ARIA. Не принимает игровых решений.
- `input` — адаптер мыши и touch/pointer. Отличает tap от drag, вычисляет
  клетку отпускания и отправляет намерение через callback.
- `application` — единственный state owner. Связывает ввод с engine, передаёт
  новый state во view, управляет restart, завершением уровня и cleanup.
- `index.ts` — composition root и реализация `MechanicHost` для общей оболочки.

Эти границы дополнительно закреплены правилами ESLint.

## Жизненный цикл хода

1. `PixelDropInputController` распознаёт выбор или перенос фигуры.
2. `PixelDropGame` преобразует это в `GameInput`.
3. `pixelDropEngine.apply` атомарно возвращает прежний state при невалидном
   ходе, новый state при размещении либо переставляет две фигуры при swap.
4. `PixelDropView.render` полностью синхронизирует графику с новым state.
5. После совпадения нормализованного цветового рисунка с target application
   один раз вызывает `onComplete`. Положение рисунка на поле не учитывается.

Такой поток исключает частично закрашенные фигуры: фигура либо помещается
целиком, либо состояние вообще не меняется.

## Уровни

Контент хранится в `src/mechanic/levels/levels.json`, schema version — `4`.
`pieceSets` позволяет переиспользовать наборы фигур, а каждый элемент `levels`
содержит собственный `target`, `initialPlacements` и тексты.

Чтобы добавить уровень:

1. Добавить target 10×10, стартовую расстановку и указать набор фигур.
2. Увеличить `levelCount` в `src/game.config.ts`.
3. Запустить `npm test`: валидатор отклонит несобираемый рисунок.
4. Добавить/обновить E2E-сценарий, если вводится новая механика.

## Правила развития

- Новое правило сначала оформляется чистой функцией или transition в `engine`.
- Новый жест добавляется в `input`, но не содержит проверок занятости клеток.
- Анимация и визуальный эффект живут в `render`, но не меняют доменный state.
- Загрузка/сохранение прогресса остаётся в shell repositories.
- Любой таймер и window-listener обязан очищаться в `destroy()`.
- Интерактивные DOM-элементы получают `data-testid` и доступное имя.
