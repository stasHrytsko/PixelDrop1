## Pixel Drop

### 1. Общее

- **Название:** Pixel Drop
- **Один абзац:** Игрок размещает заранее заданные цветные полимино на сетке
  8×8 так, чтобы непрерывные одноцветные группы («раны») в каждой строке и
  каждом столбце точно совпали с числовыми подсказками по краям поля.
  Подсказки не скрывают картинку — они задают спецификацию правильного поля.
  Залипание даёт момент вывода: игрок пересекает ограничения строки и
  столбца, понимает, что сюда физически может лечь только эта фигура, ставит
  её и видит, как обе оси сходятся. В финале заполненное поле раскрывается
  как цельная пиксельная композиция.
- **Жанр / аналог:** упаковочный пазл (packing puzzle). «Как Block Puzzle, но
  с системой ограничений и нотацией из нонограммы».

### 2. Цель и условия

- **Цель уровня:** разместить фигуры так, чтобы цветные раны каждой строки и
  каждого столбца совпали со своими подсказками.
- **Условие ПОБЕДЫ:** фактическая последовательность ранов `{ count, color }`
  для всех восьми строк и всех восьми столбцов полностью совпадает с
  `rowHints` и `colHints`. Совпадение с заранее сохранённым эталонным
  решением **не** требуется: если подсказкам удовлетворяет несколько
  раскладок, победными считаются все.
- **Условие ПОРАЖЕНИЯ:** проиграть нельзя, лимитов нет. Состояния `lose` в
  движке не существует.

Уточнения, чтобы не было двусмысленности:

- Ситуация, когда ни одна доступная фигура никуда не влезает, — это
  **тупик**, а не поражение. Уровень продолжается, доступны Undo и Restart.
- `undoBudget` ограничивает только число откатов. Число постановок, попыток
  и рестартов не ограничено, прогресс при рестарте не теряется.
- Ходы не ограничены, таймера нет.
- **Расширение контракта D-007 не требуется** — нового условия поражения не
  вводится.

### 3. Правила

#### Старт уровня

1. Движок загружает объект уровня из `levels.json`, создаёт пустую сетку
   8×8, отмечает активную область (`activeCells`), кладёт в трей первые три
   фигуры очереди, очищает историю и устанавливает исходный `undoBudget`.
2. Фигуры выдаются строго в порядке, заданном в уровне. Случайного выбора
   или генерации нет.
3. Каждая фигура состоит из 1–5 клеток. Каждая клетка фигуры имеет
   фиксированные `offset` и `color`. Вращать и отражать фигуру нельзя.
4. Якорь фигуры — её первая клетка в порядке чтения (сверху вниз, слева
   направо); у якоря `offset = [0, 0]`. У остальных клеток
   `offset.row ≥ 0`, `offset.col` может быть отрицательным (например у
   Z-образных форм).
5. На старте все линии находятся в состоянии `pending` (см. п. 20). Ничего
   не подсвечено как ошибка.

#### Выбор фигуры

1. Тап по занятому слоту трея выбирает находящуюся в нём фигуру.
2. Тап по уже выбранной фигуре оставляет её выбранной; дополнительного
   эффекта нет.
3. Тап по другому занятому слоту переносит выбор на эту фигуру.
4. Тап по пустому слоту трея ничего не делает.
5. Тап по неинтерактивной области интерфейса снимает выбор.

#### Размещение

1. Тап по клетке поля без выбранной фигуры ничего не делает. Поле нельзя
   редактировать напрямую — только фигурами.
2. Тап по клетке поля с выбранной фигурой делает эту клетку якорной
   позицией. Для каждой клетки фигуры движок вычисляет
   `targetRow = anchorRow + offset.row`, `targetCol = anchorCol + offset.col`.
3. Размещение валидно только если **каждая** клетка фигуры одновременно:
   находится внутри активной области и попадает в пустую клетку.
4. Если хотя бы одна клетка выходит за пределы активной области, размещения
   не происходит. Поле, трей, история и `undoBudget` не меняются. Фигура
   остаётся выбранной. Рендерер показывает короткую анимацию ошибки.
5. Если хотя бы одна клетка попадает на занятую клетку, поведение идентично
   п. 14.
6. При валидном размещении все клетки фигуры записываются в `grid` со своими
   цветами.
7. При валидном размещении в `history` добавляется один `PlacedMove` с
   `pieceId`, исходным `traySlot` и списком занятых клеток.
8. При валидном размещении использованный слот трея становится `null`, а
   выбор сбрасывается (`selectedPieceIdx = null`).
9. После каждого валидного размещения и после каждого успешного Undo движок
   пересчитывает состояние всех восьми строк и всех восьми столбцов.

#### Состояние линии

1. Раны линии читаются по порядку: ран — максимальная непрерывная
   последовательность непустых клеток одного `ColorId`. Пустая клетка
   закрывает ран. Смена цвета между двумя соседними занятыми клетками
   закрывает текущий ран и открывает новый. Неактивная клетка считается
   всегда пустой и тоже закрывает ран.
2. Фактическая последовательность ранов совпадает с подсказкой, только если
   одинаковы: число ранов, `count` каждого рана, `color` каждого рана и их
   порядок.
3. Каждая линия находится ровно в одном из трёх состояний:
    - **`ok`** — раны линии точно совпали с подсказкой. Пустая линия с
      пустой подсказкой тоже `ok`.
    - **`wrong`** — выполнено хотя бы одно условие: (а) в линии не осталось
      пустых активных клеток и раны не совпали; (б) в линии есть `ColorId`,
      которого нет в подсказке; (в) какой-то `ColorId` образует ран длиннее
      заявленного в подсказке; (г) какой-то `ColorId` образует в линии
      больше одного рана.
    - **`pending`** — все прочие случаи: линия ещё не готова, но и не
      сломана.
4. Подсказки строки читаются слева направо, подсказки столбца — сверху
   вниз. Число показывает длину рана, `ColorId` и его иконка — тип рана.
5. Между ранами разных цветов может находиться любое количество пустых
   клеток, включая ноль.
6. В каждой строке и каждом столбце один `ColorId` может образовывать
   максимум один непрерывный ран. Уровень, нарушающий это, невалиден для
   авторинга (раздел 6).

#### Победа

1. После каждого валидного размещения движок выполняет проверку победы.
2. Если хотя бы одна линия не в состоянии `ok` — уровень продолжается.
3. Если все восемь строк и все восемь столбцов в состоянии `ok`,
   устанавливается `gameState = 'won'`.
4. При `gameState = 'won'` весь дальнейший ввод игнорируется до перезапуска
   уровня или перехода на следующий.
5. Уровень завершается только по условию победы. Других способов завершить
   уровень нет.

#### Добор трея

1. Если после постановки все три слота пусты и победа не достигнута, движок
   берёт следующие три фигуры очереди в исходном порядке.
2. Если в очереди осталось меньше трёх фигур, загружаются все оставшиеся,
   остальные слоты остаются `null`.
3. Если очередь исчерпана, новые фигуры не появляются. В корректно
   свёрстанном уровне это состояние достижимо только вместе с победой.

#### Undo

1. Тап по Undo при пустой истории ничего не меняет; кнопка неактивна.
2. Тап по Undo при `undoBudget = 0` не меняет состояние уровня; рендерер
   показывает сообщение «Откаты закончились», кнопка неактивна.
3. Тап по Undo при непустой истории и `undoBudget > 0` снимает последний
   `PlacedMove`: его клетки очищаются, фигура возвращается ровно в тот
   `traySlot`, из которого была поставлена, `undoBudget` уменьшается на 1,
   выбор сбрасывается, состояния линий пересчитываются.
4. Undo откатывает только последний ход. Выбрать более ранний нельзя. За
   один тап отменяется ровно один ход.

#### Тупик

1. Если ни одна фигура текущего трея не имеет ни одной валидной позиции в
   активной области, движок устанавливает `isStuck = true` и рендерер
   показывает сообщение «Нет ходов — откати или начни заново».
2. При `isStuck = true` уровень не завершается, штрафа нет, состояние
   `playing` сохраняется.
3. Если после Undo снова существует хотя бы одна валидная постановка,
   `isStuck` возвращается в `false`.

#### Жизненный цикл уровня (зона shell)

1. Restart доступен в любой момент, включая `undoBudget = 0`, и ничего не
   стоит: `grid` очищается, очередь фигур возвращается к началу, трей
   получает первые три фигуры, история очищается, `undoBudget`
   восстанавливается, выбор и `isStuck` сбрасываются.
2. Переход на следующий уровень доступен только при `gameState = 'won'` и
   выполняет полную инициализацию нового уровня (п. 1).
3. При победе, если номер завершённого уровня больше сохранённого прогресса,
   прогресс обновляется и сохраняется.
4. Restart прогресс не изменяет.

**Критерий полноты:** пункты 6–12, 14–15, 34–36, 41–42 покрывают все
возможные жесты — тап по занятому слоту, по пустому слоту, по своей фигуре,
по клетке с выбором и без, по фону, Undo в трёх состояниях, Restart, Next
Level. Для каждого исход задан однозначно.

### 4. Состояние уровня

```tsx
type GameState = 'playing' | 'won'

type ColorId = 'red' | 'blue' | 'green' | 'yellow' | 'purple'

type Cell = null | { color: ColorId }

type Run = { count: number; color: ColorId }
type LineHint = Run[]

type LineStatus = 'ok' | 'pending' | 'wrong'

type PieceCell = { offset: [number, number]; color: ColorId }
type Piece = { id: string; cells: PieceCell[] }

type PlacedMove = {
  pieceId: string
  traySlot: number
  cells: { row: number; col: number; color: ColorId }[]
}

type LevelState = {
  gameState: GameState

  grid: Cell[][]
  // Текущее содержимое сетки 8×8.

  activeCells: boolean[][]
  // Клетки, доступные для размещения на этом уровне.

  rowHints: LineHint[]
  colHints: LineHint[]
  // Целевые последовательности ранов для восьми строк и восьми столбцов.
  // За уровень не меняются.

  trayPieces: Piece[]
  // Полная детерминированная очередь фигур уровня.

  nextPieceIndex: number
  // Индекс следующей фигуры очереди, ещё не выданной в трей.

  tray: (Piece | null)[]
  // Три текущих слота. null = слот использован.

  selectedPieceIdx: number | null
  // Индекс выбранного слота трея или null.

  lineStatus: { rows: LineStatus[]; cols: LineStatus[] }
  // Что показывать у каждой подсказки. Производное от grid и hints,
  // хранится, чтобы не пересчитывать на каждый кадр.

  history: PlacedMove[]
  // Валидные постановки в порядке совершения. Основа Undo.

  undoBudget: number
  // Оставшееся число доступных откатов.

  isStuck: boolean
  // true, если ни одна фигура трея не имеет валидной позиции.
}
```

**Чего в состоянии механики намеренно нет:**

- `previewCells` — производное от `selectedPieceIdx` и `grid`. Движок отдаёт
  чистую функцию «валидные якоря для фигуры», рендерер решает, как это
  рисовать.
- `level`, `bestLevel`, `currentLevel` — это жизненный цикл и прогресс, ими
  владеет shell. Механика знает только текущий уровень как данные и
  сообщает наружу о его завершении.

### 5. Ввод

```tsx
type GameInput =
  | { type: 'tap_piece'; traySlot: 0 | 1 | 2 }   // тап по слоту трея
  | { type: 'tap_cell'; row: number; col: number } // тап по клетке поля
  | { type: 'tap_background' }                     // тап по неинтерактивной области
  | { type: 'tap_undo' }                           // тап по кнопке отката
```

Один тип на один жест. Свайпов нет, drag нет, жеста вращения нет.

Restart и переход на следующий уровень в `GameInput` не входят: это команды
жизненного цикла, их подаёт shell, а движок отвечает на них полной
переинициализацией (п. 1). Если прототип собирается вне shell, они
добавляются как `tap_restart` и `tap_next_level` с поведением п. 41–42.

### 6. Контент уровня

```tsx
type LevelConfig = {
  id: number
  gridSize: 8

  activeCells: [number, number][]
  // Клетки, доступные для размещения. На поздних уровнях — вся сетка.
  // Ограничение прототипа: активная область должна быть прямоугольником.
  // Иначе появляется дырка посреди линии, и правило п. 20 начинает резать
  // ран в неочевидном для игрока месте.

  rowHints: LineHint[]
  colHints: LineHint[]
  // Описывают только активную часть своей линии.
  // Полностью неактивная линия получает пустую подсказку [].

  trayPieces: Piece[]
  // Полный набор фигур уровня в фиксированном порядке появления.

  undoBudget: number

  onboardingStep:
    | 'runs'            // чтение «число + иконка»
    | 'forcing'         // форсинг по сумме ранов
    | 'intersection'    // пересечение строки и столбца
    | 'repeated_color'  // выбор между фигурами одного цвета
    | 'multicolor'      // многоцветные фигуры
    | null
}
```

**Авторинг-проверки. Уровень без прогона солвером — не уровень.** Прежде чем
попасть в `levels.json`, уровень обязан пройти:

1. Существует хотя бы одна раскладка фигур, удовлетворяющая всем
   `rowHints` и `colHints` — с учётом форм, фиксированных цветовых узоров и
   отсутствия вращения и отражения.
2. Для каждого `ColorId`: число клеток этого цвета в фигурах = сумме его
   ранов по строкам = сумме его ранов по столбцам.
3. Ни в одной строке и ни в одном столбце цвет не образует больше одного
   рана (п. 25).
4. Если решений несколько — это допустимо, все они победные, но автор
   обязан знать их число: множественность снижает остроту вывода.

Солвер — инструмент авторинга и в рантайм не попадает.

#### Прогрессия: 9 уровней, 3 полосы

Растут семь параметров: активная область ↑, размер фигур ↑, неоднозначность
форм ↑, повторяющиеся цвета ↑, число ранов в линии ↑, доля многоцветных
фигур ↑, плотность заполнения ↑.

Главная ручка — **повторяющиеся цвета**. Пока каждая фигура уникального
цвета, цвет сам диктует ход. Как только цветов меньше, чем фигур, появляется
вопрос «который из них и куда именно» — и начинается настоящая дедукция.

| Полоса | Уровни | Активная зона | Цветов | Фигуры |
| --- | --- | --- | --- | --- |
| 1 — обучение | 1–3 | маленькая | 2 | 1–3 клетки, простые формы, роли цветов различимы |
| 2 — основная дедукция | 4–6 | растёт | 3–4 | 3–4 клетки, L / T / Z, один цвет у нескольких фигур |
| 3 — комбинация | 7–9 | ближе к полной 8×8 | 4–5 | до 5 клеток, растёт доля многоцветных |

По уровням:

1. Чтение нотации «число + иконка».
2. Форсинг по сумме: сумма ранов равна длине активной линии, линия
   определена без единой постановки.
3. Первое обязательное пересечение ограничений строки и столбца.
4. Выбор между двумя фигурами одного цвета.
5. Усиленные пересечения строк и столбцов.
6. Повторяющиеся цвета плюс сложные формы одновременно.
7. Ввод многоцветных фигур: одна постановка меняет раны сразу в нескольких
   цветах.
8. Многоцветность плюс повторяющиеся цвета.
9. Все механики вместе, максимальная плотность.

**Undo не используется как ручка сложности.** Базовое значение прототипа —
`3` на всех уровнях, точная модель `[TBD playtest]`. Если первая полоса
окажется фрустрирующей, первое, что стоит попробовать, — поднять бюджет на
уровнях 1–3, а не упрощать сами уровни.

### 7. Визуал

Фактические цвета берутся только из `tokens.css`. В `levels.json` лежат
исключительно `ColorId`.

**Поле**

- Квадратная сетка 8×8, каждая клетка — отдельная плитка.
- Неактивные клетки визуально отличаются от пустых активных и не реагируют
  на тап.
- Слева от каждой строки и сверху от каждого столбца стоит hint-ячейка,
  выровненная по своей линии.
- Hint-ячейка — последовательность чисел; рядом с каждым числом стоит
  иконка его `ColorId`.
- Та же иконка присутствует на клетках фигур этого `ColorId`. Дублирование
  сквозное и обязательное: без иконки на числе игрок, не различающий цвета,
  видит символ на фигуре, но не понимает, к какой подсказке она относится,
  и уровень становится непроходимым.

**Фигуры**

- Состоят из квадратных клеток, геометрия соответствует `offset`.
- Не вращаются и не отражаются.
- Многоцветная фигура показывает тип каждой своей клетки отдельно.

**Состояния**

- **Выбрано:** фигура в трее слегка увеличивается, появляется контур
  выделения, ~150 мс. Одновременно на поле подсвечиваются все клетки-якоря,
  куда эта фигура влезает целиком. Подсветка показывает только
  геометрическую влезаемость, не правильность по подсказкам, поэтому решение
  не выдаёт. Побочный эффект: тупик становится видимым — подсветки нет ни у
  одной фигуры.
- **Успешная постановка:** короткий pop / всплеск яркости на поставленных
  клетках, ~200 мс, плюс короткая хаптика при поддержке устройства.
- **Ошибка размещения:** короткий flash / shake на тапнутой клетке, ~200 мс,
  состояние не меняется, хаптика более резкая.
- **Линия `ok`:** hint-ячейка целиком переходит в состояние «выполнено»,
  мгновенно, без анимации.
- **Линия `wrong`:** hint-ячейка переходит в состояние «ошибка», мгновенно.
- **Линия `pending`:** hint-ячейка в нейтральном состоянии.
- **Победа:** линии сетки уходят на второй план, клетки композиции
  проявляются волной от центра, 400–600 мс. Это главный эмоциональный укол,
  и он происходит на самом поле. Оверлей «Уровень пройден» с кнопкой
  следующего уровня появляется только после анимации и относится к shell.

**HUD:** название, номер уровня, оставшийся `undoBudget` на кнопке Undo,
кнопка Restart. Таймера нет. Счётчика ходов нет.

### 8. Онбординг

1. «Число показывает, сколько одинаковых клеток должно идти подряд.»
2. «Иконка рядом с числом показывает, какого типа должны быть эти клетки.»
3. «Подсказки слева относятся к строкам, сверху — к столбцам. Прятать
   картинку они не пытаются: это условие, а не загадка.»
4. «Выбери фигуру и тапни клетку, куда хочешь её поставить.»
5. «Ищи место, которое подходит и строке, и столбцу одновременно.»
6. «Откаты ограничены — сначала проверь ход, потом ставь.»

### 9. Явно ВНЕ рамок

**Решения фундамента (менять только осознанно):**

- Без вращения и отражения фигур — четыре ориентации на фигуру взрывают
  пространство вывода и кратно усложняют авторинг и солвер.
- Без скрытой картинки и дедукции изображения — подсказки это спецификация,
  а не секрет. Классическое правило нонограммы здесь не действует.
- Без нескольких ранов одного `ColorId` в одной линии — один цвет равен
  одному куску.
- Без случайного появления фигур в рантайме — случайность делает уровень
  потенциально нерешаемым.
- Без сверки игрока с единственным сохранённым решением — победа
  определяется подсказками.

**Вне прототипа:**

- Без процедурной генерации уровней.
- Без drag-and-drop и свайпов.
- Без кнопки подсказки и автоматического решения.
- Без комбо, множителей, очков, лидерборда, ежедневных заданий.
- Без backend, auth и сети во время игры.
- Без сохранения промежуточного состояния уровня между сессиями —
  сохраняется только прогресс по уровням.
- Без исчезновения заполненных строк и столбцов: поле копится до победы.
- Без оптимизации под landscape — портрет, при повороте вёрстка не
  ломается.
- Без обязательного звука; отклик даёт хаптика.
- Без отдельного режима для дальтоников — иконки являются постоянной частью
  базового интерфейса.
- Без состояния поражения, ограничения ходов и таймера.
- Без штрафа при тупике.
- Модель Undo сверх базового `undoBudget = 3` не расширяется до завершения
  плейтеста.
