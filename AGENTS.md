# Project instructions

## Product documentation is mandatory

Before changing gameplay, UI, onboarding, levels, progression, architecture,
platform behavior, analytics, or product scope, read `tech document.md`.

Every such change must update `tech document.md` in the same commit:

- keep the description of shipped behavior accurate;
- update contract versions and acceptance criteria when affected;
- move completed work out of Backlog;
- append a dated entry to the change log;
- update `docs/rules.md` when player-facing rules change.

An implementation is not complete while the product document is stale. Never
describe planned work as shipped functionality.
